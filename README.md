Αντικειμενοστρεφής Προγραμματισμός
Εργασία Ακαδημαϊκού Έτους 2025-2026
1 Γενικά
Στο πλαίσιο της εργασίας καλείστε να σχεδιάσετε και να υλοποιήσετε σε Java μια desktop εφαρμογή
για τη διαχείριση ενοικιάσεων αυτοκινήτων. Η εφαρμογή θα πρέπει να διαθέτει γραφικό περιβάλλον
χρήστη (GUI), να αποθηκεύει δεδομένα σε αρχεία και να προσφέρει βασικές λειτουργίες σε μια
εταιρία ενοικίασης.
Η εφαρμογή που θα αναπτύξετε θα πρέπει να υποστηρίζει ένα μηχανισμό σύνδεσης (login) για τους
χρήστες της εφαρμογής. Την εφαρμογή μπορούν να τη χρησιμοποιούν μόνο οι υπάλληλοι της εταιρίας
ενοικίασης και όχι πελάτες. Όλοι οι υπάλληλοι θα πρέπει να έχουν κάποιον λογαριασμό μέσω του
οποίου θα αποκτούν πρόσβαση στην εφαρμογή, και όλοι θα πρέπει να έχουν πρόσβαση στην ίδια
πληροφορία (όλοι δηλαδή βλέπουν τα ίδια).
Το πρόγραμμα θα πρέπει να αρχικοποιείται με ικανοποιητικό αριθμό χρηστών και να έχει
ικανοποιητικό αριθμό καταχωρημένων αυτοκινήτων με τις απαραίτητες πληροφορίες. Η χρήση
αρχείων είναι απαραίτητη για την αποθήκευση των credentials των χρηστών, των πληροφοριών των
αυτοκινήτων, των ενοικιάσεων και γενικά όλων των δεδομένων και αλλαγών που γίνονται κατά τη
διάρκεια χρήσης του προγράμματος, για να είναι διαθέσιμα και μετά τον τερματισμό του. Για
παράδειγμα, αν γίνει μια ενοικίαση ενός αυτοκινήτου και τερματιστεί το πρόγραμμα, την επόμενη
φορά που θα τρέξει ξανά το πρόγραμμα, θα πρέπει να είναι στην ίδια κατάσταση ακριβώς πριν τον
τελευταίο τερματισμό, δηλαδή το αυτοκίνητο να είναι ενοικιασμένο.
Σημαντικό: Οι κλάσεις της διασύνδεσης (JFrames, κτλ.) θα πρέπει να είναι σε διαφορετικό Java
πακέτο (package) από τις κλάσεις που υλοποιούν την λογική. Χρησιμοποιήστε για ονόματα πακέτων
τα “gui” και “api” για τις κλάσεις διασύνδεσης και λογικής, αντίστοιχα. Η ύπαρξη κώδικα λογικής
σε κλάσεις διασύνδεσης θα μετρήσει αρνητικά στην αξιολόγηση.
2 Υποβολή
Η εργασία θα πρέπει να παραδοθεί μέχρι τις 05/01/2026 23:59:59 και μετράει κατά 20% στον τελικό
βαθμό του μαθήματος. Θα πρέπει να γίνει υποχρεωτικά από ομάδες των δύο ατόμων, τα οποία θα
πρέπει να δουλέψουν συνεργατικά. Μπορείτε να χρησιμοποιήσετε το forum που υπάρχει στο elearning
στην ενότητα της εργασίας για να έρθετε σε επαφή με άλλους φοιτητές και να δημιουργήσετε ομάδα.
Η προθεσμία είναι αυστηρή, χωρίς τη δυνατότητα παράτασης, έτσι ώστε να υπάρχει χρόνος για τους
διδάσκοντες να ελέγξουν τις υποβολές μέχρι την προφορική εξέταση που θα γίνει στην εβδομάδα των
αναπληρώσεων (θα ανακοινωθεί πρόγραμμα).
Η εργασία θα πρέπει υποχρεωτικά να υλοποιηθεί ως project στο IntelliJ. Για όνομα του project
χρησιμοποιήστε το CarRent_AEM1_AEM2. Κάθε ομάδα θα πρέπει να υποβάλλει ένα zip με το In-
telllij project στο elearning [link]. Η υποβολή θα πρέπει να γίνει μόνο από το ένα μέλος της ομάδας.
3 Αξιολόγηση
Για την αξιολόγηση των εργασιών θα συνεκτιμηθεί:
● Η συνεισφορά του κάθε μέλους της ομάδας.
● Υλοποίηση λογισμικού (πληρότητα λειτουργιών, ποιότητα υλοποίησης, ευχρηστία). Το
πρόγραμμά σας θα πρέπει να αξιοποιεί βασικές έννοιες της αντικειμενοστρεφούς
προγραμματιστικής προσέγγισης, όπως κληρονομικότητα. Η έλλειψη
αντικειμενοστρεφούς σχεδίασης θα ληφθεί αρνητικά υπόψη κατά την αξιολόγηση.
● Η πληρότητα τεκμηρίωσης / Javadoc εντός του κώδικα (ποσότητα/ποιότητα σχολίων,
τεκμηρίωση κλάσεων, μεθόδων, παραμέτρων και επιστρεφόμενων τιμών μεθόδων, κτλ.).
● Η επίδοση κάθε φοιτητή/φοιτήτριας στην προφορική εξέταση της εργασίας.
Η συμμετοχή στην προφορική εξέταση είναι υποχρεωτική για την καταχώρηση βαθμολογίας
στην εργασία.
4 Βασικές Οντότητες
Η εφαρμογή θα πρέπει να περιλαμβάνει τις παρακάτω βασικές οντότητες:
• Αυτοκίνητο: Αναπαριστά ένα αυτοκίνητο που μπορεί να ενοικιαστεί.
o id: Μοναδικός κωδικός αυτοκινήτου.
o πινακίδα: Η πινακίδα του αυτοκινήτου.
o μάρκα: Μάρκα του αυτοκινήτου.
o τύπος: Για παράδειγμα, SUV, sedan, κτλ.
o μοντέλο: Συγκεκριμένο μοντέλο του αυτοκινήτου (π.χ., Corolla, Civic, Focus).
o έτος κατασκευής: Το έτος κατασκευής του αυτοκινήτου.
o χρώμα: Το χρώμα του αυτοκινήτου.
o κατάσταση: Διαθέσιμο ή Ενοικιασμένο.
• Πελάτης: Αναπαριστά έναν πελάτη που νοικιάζει αυτοκίνητα.
o ΑΦΜ: Μοναδικός αριθμός φορολογικού μητρώου.
o ονοματεπώνυμο: Ονοματεπώνυμο πελάτη.
o τηλέφωνο: Τηλέφωνο επικοινωνίας.
o email
• Ενοικίαση: Αναπαριστά μια ενοικίαση αυτοκινήτου.
o κωδικός ενοικίασης: Μοναδικός κωδικός ενοικίασης.
o αυτοκίνητο: Αναφορά στο ενοικιαζόμενο αυτοκίνητο.
o πελάτης: Αναφορά στον πελάτη που νοικιάζει το αυτοκίνητο.
o ημερομηνία έναρξης: Ημερομηνία έναρξης της ενοικίασης.
o ημερομηνία λήξης: Ημερομηνία λήξης της ενοικίασης.
o υπάλληλος: Αναφορά στον υπάλληλο της εταιρίας που καταχώρησε την ενοικίαση.
• Υπάλληλοι: Αναπαριστά τους χρήστες του συστήματος
o ονοματεπώνυμο
o username: μοναδικό για κάθε χρήστη.
o email: μοναδικό για κάθε χρήστη.
o password
5 Βασικές Λειτουργίες
Η εφαρμογή θα πρέπει να υποστηρίζει τις εξής λειτουργίες μέσω κατάλληλων φορμών:
• Προσθήκη / Επεξεργασία Αυτοκινήτου: Εισαγωγή / επεξεργασία αυτοκινήτου με όλα τα
απαιτούμενα στοιχεία (μάρκα, μοντέλο, έτος, χρώμα, κατάσταση).
• Προσθήκη / Επεξεργασία Πελάτη: Καταχώρηση / επεξεργασία ενός πελάτη με όλα τα
απαιτούμενα στοιχεία. Η καταχώρηση / επεξεργασία πελάτη θα πρέπει να γίνεται ανεξάρτητα
από την ενοικίαση, δηλαδή πρώτα θα καταχωρείται ο πελάτης, αν δεν υπάρχει ήδη, και μετά
θα ξεκινάει η διαδικασία ενοικίασης.
• Αναζήτηση Αυτοκινήτου: Αναζήτηση αυτοκινήτου βάσει μάρκας, πινακίδας, μοντέλου,
χρώματος ή κατάστασης (θα πρέπει να υποστηρίζεται και ο συνδυασμός κριτηρίων, π.χ.
αναζήτηση με μάρκα και χρώμα ταυτόχρονα).
• Αναζήτηση Πελάτη: Αναζήτηση πελάτη με βάση το ΑΦΜ, ονοματεπώνυμο ή τηλέφωνο.
• Ενοικίαση Αυτοκινήτου: Επιλογή πελάτη και αυτοκινήτου για νέα ενοικίαση, με έλεγχο
διαθεσιμότητας και συμπλήρωση της σχετικής φόρμας με όλα τα απαραίτητα στοιχεία
(ημερομηνίες, κτλ.).
• Επιστροφή Αυτοκινήτου: Επιστροφή ενοικιασμένου αυτοκινήτου και αυτόματη ενημέρωση
της διαθεσιμότητας του αυτοκινήτου που επιστρέφεται.
• Προβολή Ιστορικού Ενοικιάσεων για Πελάτη: Εμφάνιση προηγούμενων και ενεργών
ενοικιάσεων για έναν συγκεκριμένο πελάτη, μαζί με όλα τα στοιχεία της κάθε ενοικίασης.
• Προβολή Ιστορικού Ενοικιάσεων για Αυτοκίνητο: Εμφάνιση προηγούμενων και ενεργών
ενοικιάσεων για ένα συγκεκριμένο αυτοκίνητο, μαζί με όλα τα στοιχεία της ενοικίασης.
• Προσθήκη χρηστών / διαγραφή: Ένας υπάρχων χρήστης θα μπορεί να προσθέτει/διαγράφει
άλλους χρήστες μέσω αντίστοιχης φόρμας.
• Σύνδεση / αποσύνδεση χρηστών: Σύνδεση διαχειριστών (login) με username και password
και επιλογή αποσύνδεσή τους από την εφαρμογή.
Σημειώσεις
• Στις φόρμες χρηστών, καταχώρησης / επεξεργασίας αυτοκινήτων και πελατών πρέπει να
εμφανίζονται κατάλληλα μηνύματα στο GUI σε περίπτωση που υπάρχει κάποιο σφάλμα στην
εισαγωγή, π.χ. κάποια υποχρεωτικά πεδία δεν έχουν τιμή ή γίνεται κάποιος άλλος έλεγχος που
αποτυγχάνει και δεν μπορεί να γίνει η καταχώρηση, π.χ. αρνητική τιμή.
• Ο Μοναδικός κωδικός ενοικίασης πρέπει να δημιουργείται αυτόματα κάθε φορά που γίνεται
μια ενοικίαση και πρέπει να είναι μοναδικός στο σύστημα.
• Ο Μοναδικός κωδικός αυτοκινήτου, η πινακίδα και το ΑΦΜ πρέπει να είναι μοναδικά στο
σύστημα, π.χ. δεν μπορεί να γίνει καταχώρηση πελάτη ή αυτοκινήτου με ΑΦΜ ή κωδικό
αυτοκινήτου που υπάρχει ήδη στο σύστημα.
• Στην ενοικίαση αυτοκινήτου, ο χρήστης θα πρέπει να επιλέγει το αυτοκίνητο και τον πελάτη
με εύχρηστο/εύκολο τρόπο. Για παράδειγμα, μπορεί να επιλέγει ένα διαθέσιμο όχημα και μέσω
μιας νέας φόρμας να αναζητεί τον πελάτη (π.χ. μέσω ΑΦΜ) που θα ενοικιάσει το όχημα, καθώς
επίσης και να εισάγει όλες τις απαραίτητες πληροφορίες, όπως ημερομηνία έναρξης και
επιστροφής του οχήματος. Ο υπάλληλος που κάνει την ενοικίαση θα συσχετίζεται αυτόματα
με την ενοικίαση, βάσει του χρήστη που είναι εκείνη την στιγμή συνδεδεμένος στην εφαρμογή.
• Ένας πελάτης μπορεί να έχει νοικιασμένα ταυτόχρονα πολλά αυτοκίνητα. Ένα αυτοκίνητο
μπορεί να είναι κάθε φορά νοικιασμένο από έναν πελάτη.
• Αντίστοιχα, η επιστροφή ενός οχήματος πρέπει να είναι εύκολη. Για παράδειγμα, ο υπάλληλος
της εταιρίας θα μπορεί να αναζητά τον πελάτη με βάση π.χ. το ΑΦΜ, ή το αυτοκίνητο με βάση
την πινακίδα, να επιλέγει την ενοικίαση από το ιστορικό και να υπάρχει επιλογή ολοκλήρωσης,
ώστε να ενημερώνεται και η διαθεσιμότητα του οχήματος.
Είστε ελεύθεροι να υλοποιήσετε με όποιον τρόπο κρίνετε εσείς καλύτερο τις διάφορες
λειτουργίες, ικανοποιώντας τις απαιτήσεις που περιγράφονται. Η σωστή σχεδίαση και
ευχρηστία του προγράμματος συμβάλει θετικά στην αξιολόγηση.

7 Μη Λειτουργικές Απαιτήσεις και Διευκρινήσεις
[7.1] Το πρόγραμμα πρέπει να υλοποιηθεί υποχρεωτικά ως IntelliJ project, όπως έχουμε δείξει
στα εργαστήρια. Το πρόγραμμά σας θα εξεταστεί μέσω του IDE τρέχοντας την main. Θα
πρέπει να υπάρχει μία μόνο main στο πρόγραμμά σας.
[7.2] Είναι απαραίτητο να ελέγξετε ότι το πρόγραμμα είναι λειτουργικό (να κάνει compile και να
τρέχει). Προτείνεται να τρέξετε το πρόγραμμά σας σε έναν υπολογιστή που δεν έχει
χρησιμοποιηθεί στην υλοποίηση (π.χ. σε κάποιον υπολογιστή στο PC Lab), ώστε να γίνουν
οι απαραίτητοι έλεγχοι. Για παράδειγμα, ένα συχνό πρόβλημα είναι η χρήση απόλυτων
διαδρομών για ανάγνωση/εγγραφή αρχείων και όχι σχετικών, με αποτέλεσμα να μην τρέχει
το πρόγραμμα σε άλλους υπολογιστές. Προγράμματα τα οποία δεν κάνουν compile και δεν
τρέχουν δεν θα βαθμολογηθούν.
[7.3] Αν χρησιμοποιήσετε εξωτερικές βιβλιοθήκες, πρέπει να βεβαιωθείτε ότι περιλαμβάνονται
στο project που θα παραδώσετε, ώστε να μην υπάρχει πρόβλημα στην εκτέλεση του
προγράμματός σας σε διαφορετικό υπολογιστή. Για παράδειγμα, μπορείτε να
χρησιμοποιήσετε JavaFX για το GUI, οπότε πρέπει να βεβαιωθείτε ότι οι αντίστοιχες
βιβλιοθήκες έχουν περαστεί στο project και μπορεί να γίνει compile/run χωρίς επιπλέον con-
figuration.
[7.4] Και τα δύο μέλη της ομάδας πρέπει να συνεισφέρουν το ίδιο στην εργασία. Μπορεί να γίνει
αρχικά ένας διαμοιρασμός των απαιτήσεων και της υλοποίησης, και ο καθένας / καθεμία να
δουλεύει ανεξάρτητα και στο τέλος να γίνει η ενσωμάτωση των επιμέρους κομματιών.
[7.5] Ο κώδικας θα πρέπει να είναι επαρκώς τεκμηριωμένος με χρήση Javadoc (σχόλια σε επίπεδο
κλάσεων, ιδιοτήτων, μεθόδων, παραμέτρων και επιστρεφόμενων τιμών). Δεν χρειάζεται Ja-
vadoc σε κλάσεις που υλοποιούν το GUI.
[7.6] Είναι υποχρεωτικό να υπάρχουν υπάλληλοι, όπως περιγράφεται στο [6.1]. Εργασίες στις
οποίες δεν μπορεί να γίνει login με τους κωδικούς που έχουν δοθεί δεν θα βαθμολογηθούν.
[7.7] Είναι απαραίτητο το πρόγραμμά σας να αρχικοποιείται με τα δεδομένα που σας δίνονται που
είναι απαραίτητα για τον έλεγχο όλων των λειτουργιών. Η αρχικοποίηση πρέπει να γίνεται
την πρώτη φορά που θα τρέξει το πρόγραμμα, και όχι κάθε φορά που τρέχει, γιατί θα χάνονται
οι αλλαγές που έχουν τυχόν γίνει.
